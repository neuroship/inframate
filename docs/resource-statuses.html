Inframate Resource Statuses

How inframate determines the state of your infrastructure resources

Three Sources of Truth

Every resource is checked against three locations. The overlap determines its status.

Code — declared in .tf files
State — tracked in terraform.tfstate
Cloud — exists in AWS

Statuses

✓

Managed

Resource is in your code, tracked in state, and exists in the cloud. Everything is in sync.

Code State Cloud
+

Pending

Resource is declared in code but hasn't been applied yet. Run terraform apply to create it.

Code State Cloud
≠

Drift

Resource is in code and state but missing from the cloud. It was deleted outside of Terraform.

Code State Cloud
?

Unmanaged

Resource exists in the cloud but isn't tracked by Terraform. Import it or leave it as-is.

Code State Cloud
×

Orphaned

Resource is in state but its code was removed. Next apply will destroy it.

Code State Cloud

Planned Actions

When Terraform plans changes, each resource gets an action label.

Create — will be provisioned
Update — will be modified in-place
Destroy — will be deleted
Replace — destroy + create
No-op — no changes needed

Status Reference

Each status at a glance with its presence pattern.

Status Presence What it means
Managed Code State Cloud Fully in sync — defined in code, tracked in state, exists in cloud
Pending Code State Cloud Declared in code but not yet applied
Drift Code State Cloud In code and state, but missing or changed in cloud
Unmanaged Code State Cloud Exists in cloud but not managed by Terraform
Orphaned Code State Cloud In Terraform state but code definition was removed

When cloud scan is skipped (--no-cloud), resources in code + state are assumed Managed, and drift / unmanaged detection is unavailable.
